# company-docs-agents

A reusable multi-agent system for reverse-engineering and documenting existing company software projects.

## Overview

This repository defines a coordinated team of AI agents, each with a specific role, that work together to analyze an existing codebase and produce comprehensive technical documentation—including architecture diagrams, API references, database schemas, deployment guides, and consolidated `.odt` deliverables.

The system is **project-agnostic**: swap out `project.brief.md` and point agents at a new repository to document any stack.

## Current Target Project

**Ticksy** by Futurense — a helpdesk/ticketing platform.  
See [`project.brief.md`](project.brief.md) for the full technology stack and documentation targets.

## Agent Roster

| Agent Name | Role |
|---|---|
| `manager-agent` | Main coordinator; user-facing entry point |
| `discovery-agent` | Repository scanning, file inventory, dependency mapping |
| `frontend-agent` | Frontend analysis (React, routing, auth, API layer) |
| `backend-agent` | Backend lead; coordinates three sub-agents below |
| `backend-api-agent` | FastAPI routers, endpoints, schemas, auth, middleware |
| `backend-domain-agent` | Business logic, ticket lifecycle, calculations, jobs |
| `backend-infra-agent` | DB sessions, AWS S3, email, Gemini/ChromaDB, reliability |
| `data-uml-agent` | Database models, ER/C4/UML diagrams, `.odt` deliverables |
| `devops-agent` | Local setup, env vars, build/deploy, onboarding guide |
| `auditor-agent` | Verification, consistency checks, security/perf audit |
| `config-updater-agent` | Meta-agent for editing agent configs and rules |

## Quick Start

### 1. Review the brief

Read [`project.brief.md`](project.brief.md) to understand the target project and expected deliverables.

### 2. Talk to `manager-agent`

Address `manager-agent` to begin:

```
manager-agent, start the document process as planned so I can understand it and tell you what to change.
```

`manager-agent` will:
1. Inspect `AGENTS.md`, `project.brief.md`, and the target project structure.
2. Present an **Execution & Documentation Plan** in `PLAN_APPROVAL.md`.
3. **Pause** for your review and feedback.
4. After approval, delegate work to specialist agents, run the auditor, and report results.

### 3. Address any agent by name

You can talk to any agent directly using its exact hyphenated name:

```
frontend-agent, list all protected routes and the roles that can access them.
backend-api-agent, document the JWT authentication flow.
auditor-agent, verify the endpoint list against the actual codebase.
config-updater-agent, add a new rule requiring all agents to include line numbers.
```

### 4. Verify documentation

Run the verification script to check documentation completeness:

```bash
python scripts/verify_docs.py
```

## Adapting for a New Project

1. Edit `project.brief.md` with the new project's stack, repo path, and deliverables.
2. Optionally run `config-updater-agent` to adjust agent prompts for the new stack.
3. Address `manager-agent` to start the documentation process.

## Rules & Safety

All agents operate under strict rules defined in `.agents/rules/`:

- **Read-only inspection** of target projects — never modify source code or production configs.
- **No fabrication** — only document what exists in code; mark unknowns as `UNKNOWN` or `NOT VERIFIED`.
- **No secret exposure** — never output API keys, tokens, passwords, or PII.
- **Cite sources** — include file paths, symbols, and line numbers wherever possible.
